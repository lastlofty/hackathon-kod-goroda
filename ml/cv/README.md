# МГТС «Код города» — состояние ТКШ и РЩ по фото (CV)

В репозитории лежат код и разметка. Фото датасета (`data/images/`), результаты (`runs/`) и обученные головы
(`models/heads.joblib`) не коммитятся: фото собираются `build_dataset.py` из исходных архивов, остальное —
командами ниже (`detect` → `cv` → `train`, около 5 минут на GPU). Команды запускаются из папки `ml/cv`.

## Окружение
Используется conda-окружение `ml` (Python 3.12, torch 2.14+cu130, transformers 5.x — проверено на RTX 5050 / sm_120).
Не хватало только `openpyxl` (доустановлен). Код совместим и с transformers 4.4x.
С нуля: `pip install -r requirements.txt` (для RTX 50xx нужен torch с CUDA ≥ 12.8).

```
conda activate ml
```

## Датасет (`data/`)
Собран из двух частей `Датасет-ДСС` скриптом `build_dataset.py`. 61 снимок, дубликатов (sha1) нет, предупреждений нет.

| папка | объект | состояние | снимков |
|---|---|---|---|
| `tksh_ok` / `rsh_ok` | ТКШ / РЩ | удовлетворительно | 10 / 10 |
| `tksh_lkp` / `rsh_lkp` | ТКШ / РЩ | повреждение ЛКП (коррозия) | 10 / 10 |
| `tksh_mp` / `rsh_mp` | ТКШ / РЩ | механические повреждения | 10 / 11 |

Файлы переименованы в `<папка>_<исходное имя>`: в исходниках `20211214.jpg` встречается в двух папках с разными снимками.
Скрипт останавливается при коллизии имён и пересобирает `images/` с нуля.

`data/labels.csv` — одна строка на снимок:
- `object_type` (TKSH/RSH), `condition` (ok/defect);
- `defect_lkp` (23), `defect_mp` (21), `mp_deformation` (17), `mp_mount` (5: крепление / «удерживается на кабеле» / падение),
  `mp_door_missing` (2) — из статуса и описания в xlsx; `defect_lkp=1` и для МП «с повреждением ЛКП»;
- `severity`: critical (крепление, 5) > high (МП, сквозная/глубокая коррозия, «отсутствует ЛКП» с учётом опечатки «Отсутстует», 23)
  > medium (коррозия, 13) > none (20);
- `status_raw`, `description` — как в xlsx; `mentions_other_object` = 1, если в описании дефект второго шкафа (4 снимка);
- `source_folder`, `original_name`, `sha1`, `width`/`height` (после EXIF-поворота).

`data/reference/Фото.1.jpg` — образец с подписанными ТКШ и РЩ, `data/abbreviations.txt` — сокращения.

```
python build_dataset.py ~/Downloads/doc-1795639519/Датасет-ДСС ~/Downloads/doc-1795639569/Датасет-ДСС --out data
```

## Решение (`solution.py`)
```
python solution.py detect   --data data --out runs/det            # --detector gdino для Grounding DINO
python solution.py evaluate --data data --det runs/det --out runs/eval
python solution.py train    --data data --det runs/det --out models
python solution.py predict  --images <папка с фото> --models models --out runs/pred
```

1. **detect** — zero-shot детекция (OWLv2 по умолчанию, Grounding DINO — `--detector gdino`). Запросы с подсказкой типа ТКШ/РЩ
   плюс «отрицательные» запросы (вентрешётка, столб, автоматы внутри): рамки, которым лучше всего подходит такой запрос,
   отбрасываются. Учтены EXIF-ориентация, паддинг OWLv2 до квадрата, NMS. Целевая рамка = лучшая рамка нужного типа (без
   рамок-столбов); если это деталь внутри рамки шкафа — берётся объемлющая рамка.
   Результат: `runs/det/preview/` (красная — целевая), `crops/`, `detections.json` (`target_source`: auto / override).
   **Ручные правки** — `data/target_overrides.json`: `{"<stem>": индекс рамки | [x1, y1, x2, y2]}` (пиксели исходного фото).
   Сейчас там 18 снимков, проверенных глазами (в основном `rsh_mp`: открытые / разрушенные / висящие щиты детектор целиком
   не находит). Координаты надёжнее индексов: индексы меняются при смене запросов или детектора.
2. **evaluate** — эмбеддинги целевых вырезов и целых кадров (DINOv2-base CLS+mean patch, CLIP ViT-L/14), кеш привязан к
   содержимому вырезов; StandardScaler + LogisticRegression(class_weight=balanced), leave-one-out; zero-shot CLIP как базовая
   линия. `runs/eval/metrics.json`, вероятности по снимкам — `runs/eval/loo_predictions.json`.
3. **train** — головы на всех 61 снимках -> `models/heads.joblib` (признаки `--features both` по умолчанию).
4. **predict** — `runs/pred/result.json` (`frames` -> `detections`, `objects` со `status` urgent/review/normal, `severity`,
   `needs_review`) + `runs/pred/annotated/`. Рамки-столбы и «групповые» рамки вокруг нескольких шкафов отбрасываются.

### Результаты (leave-one-out, 61 снимок; AUC / recall / precision; 18 ручных правок рамок)

| задача | вырез CLIP | вырез both | кадр CLIP | zero-shot CLIP (вырез) |
|---|---|---|---|---|
| object_type | 0.94 / 0.80 / 0.86 | **0.97** / 0.90 / 0.96 | 0.84 / 0.67 / 0.77 | — |
| defect_any | 0.96 / 0.98 / 0.91 | **0.97** / 0.98 / 0.89 | 0.83 / 0.85 / 0.81 | — |
| defect_lkp | **0.93** / 0.74 / 0.77 | 0.91 / 0.70 / 0.84 | 0.80 / 0.52 / 0.71 | 0.93 |
| defect_mp | **0.96** / 0.76 / 0.84 | **0.96** / 0.67 / 0.88 | 0.89 / 0.62 / 0.87 | — |
| mp_mount | 0.63 / 0 / 0 | 0.70 / 0.20 / 0.50 | 0.66 / 0 / 0 | — |

Влияние качества вырезов (AUC, вырез CLIP): без правок → 14 правок → 18 правок

| задача | auto | 14 | 18 |
|---|---|---|---|
| object_type | 0.85 | 0.92 | 0.94 |
| defect_any | 0.89 | 0.94 | 0.96 |
| defect_lkp | 0.73 | 0.86 | 0.93 |
| defect_mp | 0.84 | 0.91 | 0.96 |

- Качество вырезов — главный рычаг: правильная рамка даёт +0.07…0.20 AUC, больше, чем выбор признаков.
- Вырез лучше целого кадра; без правок вырез по коррозии (0.73) хуже целого кадра (0.80).
- `mp_mount` (5 примеров) не обучается — нужен целый кадр (контекст «висит на кабеле») и больше данных.
- Эксперимент: выбор целевой рамки zero-shot CLIP («тип», «ржавый/целый», «шкаф, а не деталь») не лучше текущей
  эвристики (41 против 43 попаданий из 61) — не внедрён. 18 промахов авто-выбора: 11 — правильная рамка найдена, но выбрана
  другая (подсказка типа OWLv2 ненадёжна), 7 — правильной рамки нет выше порога (разбитые/открытые РЩ).

### Итоговая модель v2 (что используется в `train` / `predict`)
```
python solution.py cv          # групповая CV + пороги на полноту 90% -> runs/eval/cv_metrics.json
python solution.py train       # мульти-разрешение (исходник + 1024 + 512 px), пороги из cv_metrics.json
python solution.py robustness  # качество в зависимости от разрешения -> runs/robust/resolution_metrics.json
python solution.py predict --images <папка>   # result.json (контракт сервиса) + report.csv + annotated/
```
- Группы: почти одинаковые снимки одного объекта (соседние номера файлов) не разделяются — 61 фото, 51 группа.
- Ансамбль с zero-shot CLIP только для коррозии (zero-shot по МП слабый — 0.57 — и портит голову).
- Групповая CV, итог: «повреждён» AUC 0.96 (полнота 0.93, точность 0.88 при пороге 0.5); механика 0.96
  (порог 0.14 -> полнота 0.91, точность 0.73); коррозия 0.92 (порог 0.33 -> 0.91 / 0.70); тип 0.97.
- Разрешение: при уменьшении фото до 384 px «повреждён» держит AUC 0.96 (без мульти-разрешения 0.97 -> 0.94);
  детекция проседает: 70% -> 57% попаданий в шкаф.
- Два порога по цене действия: «На проверку» — порог полноты 90%; «Срочно» (P1/P2) — только при p >= 0.5,
  иначе объект идёт «На проверку». Механика «Срочно» на групповой CV: точность 0.93 (14 из 15), полнота 0.67.
- Панорамы (20 шт., 896x576, не использовались для настройки): шкафы на 9 из 20 кадров, 19 объектов —
  1 «Срочно», 13 «На проверку», 5 «Без замечаний»; 16 ложных срабатываний на кнопке зума интерфейса карт
  (артефакт скриншота); мелкие объекты (12–70 px) -> много «требует проверки».

### Выход: статус, приоритет, рекомендация
`objects[]` в `result.json`: `status` (urgent/review/normal — статусы сервиса), `verdict` (ok/defect/unknown),
`priority_level` 1–4 (1 — крепление, 2 — механика, 3 — коррозия, 4 — нет дефекта), `defect`, `defects`,
`defect_score`, `severity`, `recommendation`; `bbox` — YOLO `[cx, cy, w, h]`. `report.csv` — таблица для бригады.

### Подключение к сервису
В бэкенд добавлены поля `priority_level`, `defects`, `severity`, `recommendation` (схема + тесты), во фронт —
приоритет и рекомендация в карточке, колонка «Приоритет» в реестре. Обработчик:
```
PYTHONPATH=<корень репозитория>:<корень репозитория>/ml/cv MGTS_MODELS=<корень репозитория>/ml/cv/models \
  python -m app.survey_worker --api http://127.0.0.1:8080 --adapter mgts_adapter:infer
```
(нужны зависимости воркера, в т.ч. `httpx2`, в окружении с torch; если на сервере задан пароль пилота —
`ACCESS_PASSWORD` в окружении воркера). Проверено сквозным прогоном: очередь → адаптер → результат принят.

### Ограничения
- 61 снимок, метки только на уровне фото; целевые рамки для 18 снимков проставлены вручную, поэтому метрики выше —
  оценка классификатора при правильном вырезе, а не всей системы. Для полностью автоматического выбора — колонка auto.
- Головы видели только вырезы настоящих шкафов: на новых фото возможны ложные срабатывания на основание столба и на рамки,
  захватившие два шкафа (видно на `Фото.1.jpg`). Нужен класс «не шкаф» (вырезы нецелевых рамок / фона).
- Grounding DINO с порогом 0.3 не находит ни одной рамки на 16 из 61 снимка — по умолчанию оставлен OWLv2.
- GPS в EXIF нет, координаты в результате `null`.
- Первый запуск скачивает модели с Hugging Face (OWLv2 ≈ 0.6 ГБ, DINOv2-base ≈ 0.35 ГБ, CLIP ViT-L/14 ≈ 1.7 ГБ,
  Grounding DINO ≈ 0.9 ГБ).
