# Обследование по результатам модели

## Что делает оператор

1. Открывает карту и загружает папку фотографий, видео или датасет YOLO Detection. К съёмке можно приложить GPX-трек. В новом обследовании видны карта, пустая лента и правая карточка. В списке обследований можно отдельно открыть демосъёмку. Каждое обследование сохраняется отдельно.
2. Как только сервер принял файлы, видит список фотографий и точки съёмки на карте. По точке или строке открывается исходный кадр. Если несколько снимков сделаны в одной точке, маркер открывает их список. Рядом отображается состояние очереди или процент обработки. Снимки без геометки доступны в списке.
3. Начинает с объектов «Срочно». Карточка открывает лучший кадр и показывает рамку модели, типы и оценку дефекта объекта, оценки на выбранном кадре, количество разных кадров и координаты. В поле «Кадр» можно выбрать другое наблюдение. Повторный выбор объекта в реестре открывает его лучший кадр. Карта показывает место фотографии и отдельно точку объекта, если её указал оператор. Когда ответ модели приходит во время просмотра снимка, открытый снимок получает рамки и вердикты. При загрузке готового пакета сразу открывается реестр объектов.
4. Подтверждает предложенный тип дефекта, вводит исправленный тип или выбирает «Дефекта нет». Решение сохраняется у объекта для всего обследования. Геометрию рамки задаёт модель.

## Формат результата

Один ответ модели относится к одному обследованию. Каждый исходный снимок имеет запись в `frames`, включая снимки с пустым `detections`. Каждый физический объект представлен одной строкой в `objects`. Объединение наблюдений, оценку опасности и выбор лучшего кадра выполняет обработчик модели. Идентификаторы уникальны в пределах обследования.

```json
{
  "frames": [{
    "frame_id": "IMG_000123.jpg",
    "lat": 55.75231, "lon": 37.71204,
    "captured_at": "2026-11-26T10:14:07+03:00",
    "detections": [{
      "det_id": "IMG_000123#2", "object_id": "OBJ-0057",
      "class": "РЩ", "score": 0.93,
      "bbox": [0.412, 0.731, 0.081, 0.034],
      "defects": ["повреждение ЛКП", "деформация"], "defect_score": 0.81
    }]
  }],
  "objects": [{
    "object_id": "OBJ-0057", "class": "РЩ",
    "lat": 55.75237, "lon": 37.71229,
    "defects": ["повреждение ЛКП", "деформация"], "defect_score": 0.94, "status": "urgent",
    "observations": ["IMG_000123#2"], "best_det_id": "IMG_000123#2"
  }]
}
```

- `bbox` использует нормализованные координаты YOLO Detection в порядке `[центр_x, центр_y, ширина, высота]`. Координаты и оценки лежат в диапазоне от 0 до 1, ширина и высота положительны. Размеры относятся к исходному изображению.
- Один `media_id` соответствует одному кадру внутри результата. Если имя кадра совпадает с именем исходного фото, явный `media_id` должен указывать на это фото.
- `frame_id` совпадает с путём фотографии в пакете или с однозначным именем файла. Для кадра, извлечённого из видео, обработчик загружает JPEG/PNG/WebP и передаёт возвращённый `media_id`.
- `lat` и `lon` передаются парой либо отсутствуют. В `frames` это место съёмки, в `objects` это место объекта. Если у исходной фотографии есть геометка, она имеет приоритет над координатами кадра из результата модели. Если у исходника нет геометки, используются координаты из результата. Координаты самого объекта приводятся отдельно в его карточке.
- `score` относится к обнаружению на кадре. `defect_score` внутри детекции относится к дефекту на этом кадре. В объекте `defect_score` относится к итоговому вердикту. Пропущенные оценки отображаются прочерком.
- `observations` содержит идентификаторы детекций именно этого объекта. `best_det_id` входит в этот список. Количество кадров считается по разным `frame_id`. Опечатки в связях дают HTTP 422 при приёме результата.
- Объект может содержать `recommendation`. Она отображается в карточке и отчёте. Если поле отсутствует, интерфейс использует рекомендацию с лучшего кадра, когда обработчик её передал.
- Дополнительное поле объекта `verdict` принимает `ok`, `defect` или `unknown`. Для исходного JSON Миши вердикт выводится из `defects` и `status`. Пустой список детекций означает отсутствие обнаружений на кадре.
- Для опасности предусмотрены `urgent`, `review`, `normal`. Внутри одной группы реестр сначала показывает более высокую уверенность в дефекте. Решение оператора хранится отдельно от оценки риска модели.

В детекции, объекте и решении оператора поле `defects` содержит список строк. Для шкафов предусмотрены «повреждение ЛКП», «деформация», «нарушение крепления» и «отсутствие двери». Пустой список совместно с вердиктом `ok` означает исправное состояние. Для прежних данных API принимает одиночное поле `defect` и при чтении возвращает список.

## Входные пакеты

Папку, созданную `ml/data/prepare.py`, можно выбрать в окне загрузки или упаковать в ZIP. API связывает каждую строку `manifest.json` с файлом в `images/` и сверяет SHA-256. Служебный отчёт и миниатюры из `review/` пропускаются. Метки из таблиц попадают в реестр, фотографии без меток остаются в списке кадров.


| Вход | Действие |
| --- | --- |
| JPG, PNG, WebP, MP4, MOV, WebM и необязательный GPX | Сохранить исходники и поставить задание в очередь CV |
| ZIP ДСС или распакованная папка с фото и XLSX | Сопоставить фото со строками таблицы в той же папке. Оба архива можно выбрать вместе |
| Фото и один JSON в формате выше | Проверить ссылки между записями и открыть готовый реестр |
| Папка YOLO Detection | Сопоставить `images/train/a.jpg` и `labels/train/a.txt`, прочитать имена классов из `data.yaml`; пустая или отсутствующая метка означает кадр без объектов |

В ДСС класс определяется по папке, дефекты и описание берутся из таблицы. Коррозия относится к повреждению ЛКП. В результате `source: "dataset"` указывает на справочные данные. Фото без строки сохраняется отдельно без вердикта. Таблица описывает состояние шкафа на каждом снимке. Привязка одного шкафа к нескольким фотографиям требует явных идентификаторов. Координаты объекта и рамка остаются `null`. Для места съёмки импорт использует полную пару GPS-координат из EXIF. Одна запись даты или времени в разделе GPS точку на карте не создаёт. Оператор может ввести широту и долготу объекта в его карточке. Карта и реестр показывают эту точку с пометкой о ручном вводе. Исходные координаты съёмки сохраняются отдельно.

Строка YOLO Detection содержит `class_id cx cy width height`. Обычный датасет не задаёт уверенность, дефект и идентичность между кадрами. При прямом импорте каждая метка становится отдельным объектом на проверку. Для агрегированного результата приложите JSON модели. Если пакет содержит оба формата, приложение использует JSON. [Спецификация YOLO Detection](https://docs.ultralytics.com/datasets/detect/)

### Геометки до получения результата CV

Бэкенд читает GPS и время съёмки из EXIF. Также можно приложить файл `coordinates.json` с координатами по имени фотографии. Его можно передать вместе с результатом, YOLO-папкой или только с исходными файлами.

```json
{"frames":[{"frame_id":"IMG_000123.jpg","lat":55.75231,"lon":37.71204,"captured_at":"2026-11-26T10:14:07+03:00"}]}
```

Явные координаты из этого файла имеют приоритет. Для фотографии без координат, но с известным временем и часовым поясом, бэкенд может использовать ближайшее измерение GPX в пределах пяти секунд. Неоднозначное измерение пропускается. Время без часового пояса для сопоставления с GPX не используется. Поле `inputs[].location_source` содержит `coordinates`, `exif` или `gpx`. Снимки размещаются по отдельным точкам вне зависимости от порядка загрузки. Расположение объекта из вердикта модели не переносит точку съёмки.

## API

Базовый путь — `/api/v1`. Загрузка принимает до 512 МиБ суммарно. Лимит JSON, YAML, TXT и отдельного GPX — 8 МиБ. При превышении лимита API возвращает HTTP 413 и удаляет файлы незавершённой загрузки.

| Запрос | Действие |
| --- | --- |
| `POST /surveys` | Multipart с повторяемым полем `files` и необязательным `name`. Папки сохраняют относительные пути в имени файла |
| `GET /surveys` | Список обследований и их состояний |
| `GET /surveys/{id}` | Входные файлы с геометками, прогресс, результат и решения |
| `POST /surveys/{id}/claim` | Взять задание из очереди. При одновременной попытке второму обработчику вернётся HTTP 409 |
| `POST /surveys/{id}/progress` | Передать `{"status":"running","percent":40}` или `{"status":"failed","percent":40,"error":"описание"}` |
| `POST /surveys/{id}/result` | Передать `frames` и `objects`. Повтор идентичного результата допустим |
| `POST /surveys/{id}/reviews` | Передать `{"object_id":"OBJ-0057","decision":"confirmed","defects":["повреждение ЛКП","деформация"]}` либо `{"object_id":"OBJ-0057","decision":"rejected"}` |
| `PATCH /surveys/{id}/object-location` | Передать `object_id`, широту `lat` и долготу `lon`. Ответ и поле `manual_locations` при чтении обследования содержат `source: "manual"` |

## Покадровое распознавание из формы загрузки

Форма запрашивает режим сервера через `GET /api/v1/surveys/inference-config`. Для пакета фотографий с необязательным GPX и `coordinates.json` поле multipart `inference_mode` выбирает встроенный исполнитель. В режиме `mock` оператор явно включает «Демораспознавание фото». В режиме `triton` обработка совместимых файлов включена по умолчанию. Без этого поля действует обычная очередь внешнего обработчика. Готовые YOLO и JSON проходят через импорт результатов, видео принимает внешний обработчик.

Сервер создаёт по одному заданию `detection` на фотографию. Фоновый исполнитель использует ту же функцию, что и `POST /api/v1/jobs/{id}/run`. Обработка продолжается после закрытия вкладки. Связь хранится в `processing_jobs.parameters.survey_id`. Рамки и оценки сохраняются в `findings`, затем в результате обследования с координатами и ссылками на фотографии. Поле `inference_mode` в ответе обследования сохраняет происхождение результатов.

Адаптер может передать `attributes.object_id`, `priority`, `verdict`, `defects` и `defect_score`. Наблюдения с одним идентификатором объединяются. Лучший кадр выбирается по уверенности в дефекте, затем по уверенности в обнаружении. Без идентификатора каждое обнаружение попадает на отдельную проверку. Оценка обнаружения показывается отдельно от оценки дефекта. Название и версия модели, метка, численная опасность и рекомендация при наличии видны в «Сведениях о детекции».

## Подключение модели

Из окружения с зависимостями бэкенда и модулем модели запустите `python -m app.survey_worker --api http://127.0.0.1:8080 --adapter my_model:infer`. Обработчик берёт задания по очереди. Для однократного прохода добавьте `--once`.

Функция Миши `infer(inputs, progress, publish_frame)` получает список файлов с полями `name`, `kind`, `id`, `url` и локальным `path`. Она может вызвать `progress(40)`, опубликовать извлечённый видеокадр через `media_id = publish_frame(path)` и должна вернуть словарь с `frames` и `objects`. Адаптер отвечает за декодирование видео, модель и агрегацию. Пока адаптер не запущен, исходная съёмка остаётся в очереди. Готовый JSON и папки YOLO можно проверить самостоятельно.

## Схема хранения для Богдана

| Таблица | Данные и связи |
| --- | --- |
| `workspaces` | Первичный ключ `id`, рабочее пространство `slug=mgts` |
| `media` | Первичный ключ `id`, внешний ключ `workspace_id`, тип, имя и URL исходника или извлечённого кадра. Для исходной фотографии сохраняются координаты, время и источник геометки. Файлы лежат в каталоге загрузок |
| `processing_jobs` | Первичный ключ `id`, внешний ключ `workspace_id`, `pipeline=mgts.defects.v1`, статус, ошибка и время обработки. В `parameters` лежат имя, ссылки на исходники и прогресс. В `result` хранится принятый JSON с идентификаторами изображений |
| `defect_reviews` | Составной первичный ключ `(job_id, object_id)`. `job_id` ссылается на `processing_jobs.id`, `object_id` проверяется по объектам результата. `decision` и `defects` содержат последнее решение оператора |

Для старой базы применяется миграция `alembic upgrade head`. В этой версии кадры, детекции и агрегированные объекты лежат в одном JSON обследования. Схему связей проверяет API до сохранения. Решение можно менять с сохранением исходного ответа модели.

## Карта

В уже настроенном браузере используется сохранённый ключ Map Tiles API. Для открытия карты новым пользователем администратор может задать отдельный браузерный ключ в `DGIS_BROWSER_KEY` и ограничить его доменом демо. Этот ключ доступен клиенту. `DGIS_API_KEY` используется сервером для геокодирования.
