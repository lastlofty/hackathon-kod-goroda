# Устойчивость к сбоям и подмене зависимостей

Документ фиксирует, почему геокодинг 2ГИС вынесен в необязательную интеграцию, как проверялась цепочка поставок и что показал эксперимент с подменой пакета.

## Проблема

`httpx2` использовался только адаптером `app/integrations/dgis.py`, но импортировался на этапе загрузки приложения: `app/main.py → app/api/router.py → app/api/geocoding.py → app/integrations/dgis.py`. Из-за этого любой сбой дистрибутива останавливал весь backend, включая `/health`, хотя геокодинг — необязательная функция.

Были воспроизведены три режима отказа на ветке до исправления:

| Состояние `httpx2` | Результат |
|---|---|
| Пакет не установлен | `ModuleNotFoundError`, сервер не стартует, exit 1 |
| Пакет при импорте бросает исключение | `RuntimeError`, сервер не стартует, exit 1 |
| Установлена опубликованная заглушка `httpx2==0.0.0` | `/health` работает, `/geocoding` отдаёт `500` с `AttributeError: module 'httpx2' has no attribute 'TimeoutException'` |

## Что изменилось

- `app/integrations/dgis.py`: импорт `httpx2` стал ленивым (`load_http_client()`), проверяется наличие `AsyncClient`, `TimeoutException`, `RequestError`; при отсутствии или несовместимости поднимается `DgisUnavailable`.
- `app/api/geocoding.py`: `DgisUnavailable` превращается в `503`, ошибки на этапе сетевого запроса — в `502`, а не в `500`.
- `tests/test_dependency_isolation.py`: поднимает реальный сервер в отдельном процессе и проверяет четыре сценария — повреждённый пакет, отсутствующий пакет, пустая заглушка и несовместимый клиент.

Матрица после исправления:

| Состояние `httpx2` | `/health` | `/geocoding` |
|---|---|---|
| Отсутствует | 200 | 503 |
| Бросает исключение при импорте | 200 | 503 |
| Пустая/несовместимая заглушка | 200 | 503 |
| Клиент падает при запросе | 200 | 502 |

Приложение продолжает работать; деградирует только интеграция 2ГИС.

## Проверка цепочки поставок

Проверялись версии, а не только имена пакетов — запрос к OSV по имени без версии возвращает все исторические advisory пакета и не означает, что текущая версия уязвима.

- OSV API (`POST https://api.osv.dev/v1/query`) для всех 46 установленных дистрибутивов: записей `MAL-*` (известные вредоносные пакеты) не найдено.
- `pip-audit -r requirements.txt`: **No known vulnerabilities found**.
- `pip-audit` для всего окружения: 14 записей только в инструментарии (`pip 25.2`, `pytest 8.4.2`), в зависимости приложения они не входят.

Реальные вредоносные пакеты не скачивались и не исполнялись. Для эксперимента использовалась собственная безобидная заглушка.

## Dependency confusion: эксперимент

Поднимались два локальных PEP 503-индекса: `private` с `httpx2 2.16.2` и `public` с заглушкой `httpx2 2.99.0`. Заглушка при импорте создавала маркер во временном каталоге и бросала `RuntimeError`.

| Условия установки | Выбранная версия |
|---|---|
| `--index-url private --extra-index-url public`, без ограничения версии | **2.99.0 из «public»** |
| Только `--index-url private` | 2.16.2 |
| Оба индекса, но `httpx2==2.16.2` | 2.16.2 |

Последствия подмены:

- на версии до исправления сервер падал при старте, код из пакета выполнился (маркер создан);
- на исправленной ветке сервер поднимался, `/health` возвращал 200, `/geocoding` — 503, маркер также создавался (импорт всё же произошёл, но был перехвачен).

Вывод: ranges вида `httpx2>=2.0,<3.0` в сочетании с `extra-index-url` допускают победу более новой версии из другого индекса. Для продакшена нужны фиксированные версии с хешами (`--require-hashes`), lock-файл и один доверенный индекс.

## Что осталось вне скоупа

- Нет lock-файла и CI, поэтому сборка не воспроизводима и проверки не запускаются автоматически.
- `.env` с ключом 2ГИС остаётся отслеживаемым файлом — ключ нужно отозвать и убрать из истории Git.
- Нет аутентификации API и проверки сигнатуры загружаемых файлов; это отдельные задачи.

Текущий код устраняет именно падение приложения из-за зависимости. Он не делает подмену невозможной — он ограничивает её последствия геокодингом.
